# Module 3 Graded Assessment 🎓

## 📖 In plain words

This isn't a new topic — it's a checkpoint. You've now covered Foundations (01), Branching (02), and Remotes (03). Before moving into the intermediate commands, this assessment checks that the fundamentals are genuinely muscle memory, not just "read about it once."

No new commands here. Just a realistic scenario that mixes everything so far: init, staging, commits, branches, merging, and working with a remote on GitHub.

---

## How this works

1. Open `TASK.md` — it's one continuous scenario, broken into checkpoints.
2. Do each checkpoint for real, in a real terminal, in a throwaway practice repo.
3. Before moving to the next checkpoint, be ready to explain out loud (or in chat) what you just did and why — not just paste the command.
4. `SOLUTION.md` has the expected commands and output, for after you've attempted it yourself.
5. Update `PROGRESS.md` at the repo root once you're done — mark this assessment complete, and only then move on to `04-intermediate/`.

This is graded the way real code review works: it's not about typing the right command, it's about explaining *why* it's the right command.

---

## ✅ What "passing" looks like

You should be able to explain, in your own words:

- The three-zone model (Working Directory → Staging → Repository) and what moves a file between each zone.
- The difference between a fast-forward merge and a 3-way merge, and why the graph looks different for each.
- What a merge conflict actually is, and how to read the `<<<<<<<` / `=======` / `>>>>>>>` markers.
- The difference between `origin` and `upstream`, and when you'd need both.
- Why `git push -u` is only needed once per branch.

If any of these feel shaky, that's useful information — go back to that module before continuing. No shame in it; muscle memory takes repetition.
